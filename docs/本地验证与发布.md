# 本地验证与发布

本文说明如何在本仓库做本地验证，以及如何将模块正式发布到 Maven Central。适用于全体库模块与示例工程。

## 1. 前置条件

- JDK 8（编译 `source` / `target` 均为 `1.8`，主 JAR 内 class major 为 52）、Maven 3.6+。
- 根 `pom.xml` 是 `io.github.gollyhu:aifei-eco-bom:1.0.0-SNAPSHOT`，兼作 **BOM + reactor 聚合器**：`dependencyManagement` 统一管理依赖版本，`<modules>` 列出全部 32 个模块。子模块不设 parent，各自通过 `<aifei.eco.bom.version>` import 根 BOM。
- **两个 SPI 声明文件必须存在**。它们被根 `.gitignore` 的 `services/` 规则忽略，需用 `git add -f` 或在 `.gitignore` 中放行后才能纳入版本库：
  - `aifei-email/src/main/resources/META-INF/services/cn.hg.aifei.email.spi.MailProvider` → 一行 `cn.hg.aifei.email.internal.smtp.SmtpMailProvider`
  - `aifei-mq/src/main/resources/META-INF/services/cn.hg.aifei.mq.internal.MqProvider` → 七行实现类（memory / rocketmq / rabbitmq / mqtt / mqtt5 / kafka / redisstream）
  - 缺失时 `ServiceLoader` 发现不到 Provider，构建会报 `no MailProvider found for type smtp` 之类的错误；`aifei-mq` 的架构门禁还会直接断言该声明文件存在。

## 2. 本地验证

```bash
cd <仓库根>

# 第一步：安装根 BOM 到本地仓库（所有后续构建的前提）
mvn -N install

# 全量验证：33 个工程一次跑完
mvn clean verify

# 或逐模块验证（必须在模块目录内执行，门禁测试依赖相对路径 src/main/java）
cd aifei-tools && mvn clean verify
```

口径说明：

- `mvn clean verify`：编译 + 测试 + 门禁，**不安装**到本地仓库。
- `mvn clean install`：在 verify 基础上安装到本地仓库；**运行 demo 前必须先执行**。
- 门禁要求 0 failure / 0 error；各模块的严格度以模块自身 `AGENTS.md` 为准。
- 集成测试默认关闭，按需开启：`-Dredis.integration=true`、`-Ddb.integration=true`、`-Dkv.integration=true`、`-Doss.integration=true`。一旦开启，连不上必须使测试失败，不得静默跳过。
- 运行 demo：先 `mvn clean install` 安装被演示的库模块，再在 demo 目录执行 `start-demo.bat`（端口与验证地址见根 `README.md` 的运行示例表）。

## 3. 正式发布（Maven Central）

### 3.1 版本纪律

- 全部模块源码主线为 `x.y.z-SNAPSHOT`；已发布的 `aifei-cache:1.1.0` 为**冻结基线**，源码主线为 `1.2.0-SNAPSHOT`，其余模块为 `1.0.0-SNAPSHOT`。
- 未正式发布前禁止去掉 `-SNAPSHOT`；具备发布配置不等于已正式发布。

### 3.2 定版步骤

1. 按语义化版本确定版本号，修改模块 `<version>`、**根 BOM 的 `dependencyManagement` 中对应条目**，以及下游模块对该模块的依赖版本（同样由根 BOM 管理）。
2. 更新该模块 `CHANGELOG.md`，写明用户可感知的新特性 / 修复 / 变更 / 已知问题。
3. 全量验证：`mvn -N install && mvn clean verify`，必须 0 failure / 0 error。
4. 确认发布配置：根 BOM 与 19 个库模块均有 `central-release` profile 与 `distributionManagement`（仅 snapshotRepository）；13 个 `*-demo` 不配置发布，**不得发布**。

### 3.3 环境准备

- 在 `~/.m2/settings.xml` 中配置 `<server><id>aifei</id>` 的 Central Portal 凭据，与 `central.publishing.server.id` 默认值一致；若已有 `ossrh` 凭据，可用 `-Dcentral.publishing.server.id=ossrh` 复用。
- 准备 GPG 密钥。profile 已使用 `--pinentry-mode loopback`，可用 `-Dgpg.passphrase=...` 传入口令；不得在 POM 中硬编码 key id 或 gpg 可执行文件路径。

### 3.4 发布顺序与命令

**必须先发布 BOM，再发布模块**，否则消费方解析不到依赖版本。

```bash
# 1) 发布根 BOM（-N 只作用于根项目）
mvn -N -Pcentral-release clean deploy

# 2) 按依赖顺序发布库模块
mvn -pl aifei-cache -Pcentral-release clean deploy
mvn -pl aifei-lock,aifei-id,aifei-tools,aifei-sa-token,aifei-i18n -Pcentral-release clean deploy
mvn -pl aifei-excel,aifei-http,aifei-job,aifei-mq,aifei-oss,aifei-pay,aifei-sentinel,aifei-sms,aifei-trace,aifei-websocket,aifei-weixin,aifei-audit,aifei-email -Pcentral-release clean deploy
```

注意：

- 不要不带 `-pl` 从根执行 `mvn deploy`，那会跑到 demo 与未配置发布的模块。
- profile 中 `autoPublish=false`、`waitUntil=validated`：命令只把 bundle 提交到 Central Portal 并等待校验，**不会自动上线**。需登录 Portal 手动点击 Publish，待状态变为 Published 后再更新文档坐标。
- SNAPSHOT 发布：不带 `-Pcentral-release` 的 `mvn deploy` 会上传到 `central-portal-snapshots`，仅对已配置 distributionManagement 的模块可用。

### 3.5 发布后

1. 在 Portal 确认构件状态为 Published，并验证坐标可解析。
2. 同步更新根 `README.md` 的模块表与依赖说明，以及各模块 README 中的坐标。
3. 源码主线切到下一个 `-SNAPSHOT`（如 `1.2.1-SNAPSHOT`）继续开发。
4. Maven Central 构件不可删除或覆盖；已发布版本有问题时只能发补丁版本。

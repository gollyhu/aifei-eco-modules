# 微信接入规范

> 版本：1.0.0 ｜ 适用对象：使用 `aifei-weixin` 接入微信公众号 / 小程序 / 微信支付的 aifei 应用
>
> 本文件是接入的**唯一规范来源**，接入前必读。行为契约的完整依据见 `docs/design.md`。

## 1. 前置条件

| 项 | 要求 |
| --- | --- |
| 运行环境 | Java 8 及以上 |
| 应用框架 | aifei 应用，且**自带 `aifei-all`**（`Handler` / `Input` / `Output` / `Log` 与 fastjson2 由其提供） |
| 依赖坐标 | `io.github.gollyhu:aifei-weixin:1.0.0` |
| 不得引入 | 被本模块禁用的依赖（`aifei-vip-arch`、`undertow`、`jedis`、`okhttp`、`jackson`、`fastjson1`、`mysql`、`druid`），清单见 `AGENTS.md` 硬性约束 |

## 2. 依赖声明

```xml
<dependency>
    <groupId>io.github.gollyhu</groupId>
    <artifactId>aifei-weixin</artifactId>
    <version>1.0.0</version>
</dependency>
```

本模块对 `aifei-all` 的依赖是 `provided`，**不会传递**：应用必须自己声明 `aifei-all`，否则编译期缺少内核类型、运行期抛 `NoClassDefFoundError`。

构建顺序：先 `cd aifei-weixin && mvn clean install`，再构建依赖它的应用模块。

## 3. 公众号回调接入

### 3.1 实现传输 SPI `WeixinIo<I>`

回调链路通过 `WeixinIo` 与具体 Web 容器解耦，共 4 个方法：

| 方法 | 实现要求 |
| --- | --- |
| `String query(I in, String name)` | 返回 URL 查询参数；不存在返回 `null`（不要返回空串） |
| `String body(I in)` | 读取原始请求体（UTF-8），完整读出 |
| `boolean isGet(I in)` | GET 请求返回 `true`（URL 首验），否则 `false`（消息回调） |
| `void replyXml(I in, String xml)` | 以 `text/xml`（UTF-8）写出响应体并**结束本次交换**；`xml` 为 `success` 时同样需要写出 |

```java
/** 骨架示意：下列私有方法由你按项目的 HIO 实现 */
public class MyWeixinIo implements WeixinIo<Input> {

    @Override
    public String query(Input in, String name) {
        return in.getStr(name);          // 取 URL 查询参数；不存在返回 null
    }

    @Override
    public String body(Input in) {
        return readBodyAsUtf8(in);       // 读取原始请求体（UTF-8）
    }

    @Override
    public boolean isGet(Input in) {
        return isGetRequest(in);         // 请求方法为 GET 时返回 true（URL 首验）
    }

    @Override
    public void replyXml(Input in, String xml) {
        writeXmlAndFinish(in, xml);      // 以 text/xml; charset=utf-8 写出并结束本次交换
    }
}
```

验签参数名与微信一致：`signature` / `msg_signature` / `timestamp` / `nonce` / `echostr` / `encrypt_type`。

`replyXml` 必须**自行写出并结束交换**，`WeixinHandler` 匹配成功后会自行闭环、不再调 `next`。

### 3.2 配置账号

```java
WeixinAccount account = WeixinAccount.of(appId, secret, token, aesKey);
settings.addHandler(new WeixinHandler<>(new MyWeixinIo(), WeixinAccountProvider.of(account), new MsgHandler() {
    @Override
    protected OutMsg processInTextMsg(InTextMsg msg) {
        return new OutTextMsg("收到：" + msg.getContent());
    }
}));
```

| 参数 | 说明 |
| --- | --- |
| `appId` / `token` | 必填，非空白 |
| `secret` | 调用 Api 时需要；仅回调用途时可传 `null` |
| `aesKey` | 公众号后台的 `EncodingAESKey`，**43 字符**；传 `null` 或空串即明文模式 |

多公众号：实现自己的 `WeixinAccountProvider`，按回调路径中的 `{appId}` 返回对应账号，未知 appId 返回 `null`（回调会被拒并回 `fail`）。

### 3.3 注册顺序（必须遵守）

`WeixinHandler` **必须注册在 `FrontHandler` 之前**。注册在后时，首验 GET 会被前端处理器渲染成首页 HTML，微信判定对接失败，且本地日志无异常。

回调地址：`https://你的域名/weixin/{appId}/msg`（前缀 `/weixin` 可自定义，构造器第一个参数）。

### 3.4 公众号后台配置

| 项 | 值 |
| --- | --- |
| 服务器地址 URL | `https://你的域名/weixin/{appId}/msg` |
| Token | 与 `WeixinAccount.of` 的 `token` 一致 |
| EncodingAESKey | 与 `aesKey` 一致 |
| 消息加解密方式 | 明文模式或安全模式均可；两种模式下 `MsgKit` 都会正确处理 |

### 3.5 业务扩展 `MsgHandler`

`MsgHandler` 提供 17 个 `protected` 钩子（8 个消息 + 9 个事件，菜单 CLICK 与 VIEW 共用 `processInMenuEvent`），全部默认返回 `null`：

- 返回 `OutMsg` → 作为被动回复返回给用户（收发方反转与时间戳由框架填充，业务无需处理）。
- 返回 `null` → 不回复，框架回 `success`。

| 类别 | 钩子 |
| --- | --- |
| 消息 | `processInTextMsg` / `processInImageMsg` / `processInVoiceMsg` / `processInVideoMsg` / `processInShortVideoMsg` / `processInLocationMsg` / `processInLinkMsg` / `processInSpeechRecognitionMsg` |
| 事件 | `processInFollowEvent` / `processInUnFollowEvent` / `processInQrCodeEvent` / `processInLocationEvent` / `processInMenuEvent` / `processInTemplateEvent` / `processInMassEvent` / `processInCustomEvent` / `processInVerifyEvent` |

可用回复类型：`OutTextMsg` / `OutImageMsg` / `OutVoiceMsg` / `OutVideoMsg` / `OutMusicMsg` / `OutNewsMsg`（图文可 `addArticle(...)` 追加多篇）。

## 4. 使用公众号 / 小程序 Api

### 4.1 装配（应用启动时一次）

```java
WxApiConfig.set(new JdkHttpKit(), new MemoryAccessTokenCache());
```

- 未装配即调用 Api 会抛 `WxApiException`。
- 传输实现可替换为自定义 `HttpKit`（接入既有连接池 / 代理时）。
- **多实例部署必须把 `MemoryAccessTokenCache` 换成共享实现**：微信在刷新 token 时会使旧 token 立即失效，且获取 token 有每日配额；各实例各自缓存会导致频繁失效与配额消耗。

### 4.2 调用

```java
WeixinAccount account = WeixinAccount.of(appId, secret, token, aesKey);

MenuApi.create(account, menuObject);
UserApi.getUserInfo(account, openId, "zh_CN");
MediaApi.uploadTemp(account, "image", file);
TemplateMsgApi.send(account, payload);
ApiResult ret = QrcodeApi.create(account, payload);
```

- Api 会自行注入 `access_token`；遇 `40001` / `42001` 自动清缓存并重试一次。
- 业务错误（`errcode` 非 0）通过 `ApiResult.isSucceed()` / `getErrorCode()` / `getErrorMsg()` 返回，不抛异常。
- OAuth2 的 `sns/*` 接口自带 `appid` / `secret`，不注入 token。
- JS-SDK 前端签名：`JsTicketApi.getTicket(account)` 取 ticket，再 `JsTicketApi.sign(ticket, nonce, timestamp, url)`。

### 4.3 小程序

```java
MiniAppAccount mini = MiniAppAccount.of(appId, secret);

Code2Session session = MiniAppApi.code2Session(mini, code);   // openid / unionid / sessionKey
MiniAppApi.subscribeSend(mini, payload);
MiniAppApi.getUserPhoneNumber(mini, code);
byte[] code = MiniAppApi.getWxacodeUnlimit(mini, payload);
```

小程序复用公众号的 token 缓存与 HTTP 装配，只需注册 `MiniAppAccount`（与公众号账号相互独立）。`Code2Session.getSessionKey()` 属敏感数据，**不得落日志或下发前端**。

## 5. 微信支付 V3 接入

### 5.1 装配

```java
PayMerchant merchant = PayMerchant.ofPem(mchId, privateKeyPem, certSerialNo, apiV3Key);

// mTLS：用商户 API 证书构造带客户端证书的 SSLContext（加载方式依部署方式自定）
WxPayConfig.set(new JdkPayHttpKit(sslContext), new PlatformCertManager(merchant));
```

| 参数 | 说明 |
| --- | --- |
| `mchId` | 商户号 |
| `privateKeyPem` | 商户 API 私钥（PKCS#8，带或不带 PEM 头均可） |
| `certSerialNo` | 商户 API 证书序列号（请求签名用） |
| `apiV3Key` | APIv3 密钥，**32 字符** |

`PlatformCertManager` 负责平台证书的下载、解密与缓存，未知序列号会触发惰性刷新（60 秒节流），无需自行拉取证书。

### 5.2 下单与查询

```java
JSONObject ret = PayApi.jsapi(merchant, appId, "商品描述", outTradeNo, notifyUrl, totalFen, openid);
PaySignature.JsapiPayParams params = PayApi.buildJsapiPayParams(appId, merchant, prepayId);  // 交给前端 wx.requestPayment
PayApi.queryByOutTradeNo(merchant, outTradeNo);
PayApi.close(merchant, outTradeNo);
PayApi.refund(merchant, outTradeNo, outRefundNo, refundFen, totalFen, notifyUrl);
```

支付接口**没有自动重试**，且非 2xx 统一抛 `WxApiException`（消息含状态码与官方 `code` / `message`），需业务自行决定补偿策略。

### 5.3 回调处理

```java
// headers = 请求头（至少含 Wechatpay-* 四项），body = 原始请求体
if (!PayNotifyKit.verify(keySource, headers, body)) {
    // 返回 4xx/5xx，微信将按策略重试
}
JSONObject transaction = PayNotifyKit.decryptResource(merchant, body);   // 或 verifyAndDecrypt(...) 一步完成
```

要求：

1. **必须自行幂等**：SDK 不做去重，微信会重复投递。以 `out_trade_no` 等业务键做幂等，重复通知直接返回成功应答。
2. **应答格式按官方规则**：成功应答 HTTP 200 或 204；失败应答 4xx/5xx 并带 `code` / `message`。
3. 回调链路不要做长耗时操作；耗时业务异步化。
4. `PlatformKeySource` 可用 `PlatformCertManager`，也可静态持有平台公钥 `pub_key.pem`。

## 6. 行为契约（不可协商）

| 契约 | 说明 |
| --- | --- |
| 无被动回复必须回 `success` | 返回空串会被微信判定超时并重试 3 次；框架已对解析失败、未知类型、业务异常统一兜底为 `success` |
| 验签失败 / 解密失败回 `fail` | 框架已处理，业务无需介入 |
| HTTP 状态码恒 200 | 回调语义由响应体承载，不要改写状态码 |
| 5 秒响应限制 | 回调链路**禁止同步调用 Api**；耗时业务转异步 |
| 幂等 | 消息按 `MsgId`、支付回调按 `out_trade_no` 由业务自行幂等 |
| 注册顺序 | `WeixinHandler` 必须在 `FrontHandler` 之前 |
| 敏感信息脱敏 | `WeixinAccount` / `MiniAppAccount` / `Code2Session` / `PayMerchant` 的 `toString` 已脱敏；日志中不要自行打印密钥、`sessionKey`、回调原文 |
| 多实例 token | 生产环境必须使用共享 `AccessTokenCache` |

## 7. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 公众号后台提交服务器地址提示失败 | `WeixinHandler` 是否注册在 `FrontHandler` 之前；`token` 是否与后台一致；`replyXml` 是否真的写出了响应体 |
| 用户消息无回复、后台看到重试 | 检查钩子是否返回 `null`（返回 `null` 即不回复）；检查业务逻辑是否超过 5 秒 |
| 安全模式下报「签名校验失败」 | `aesKey` 与后台 `EncodingAESKey` 是否一致（43 字符）；是否误把 `token` 填成 `aesKey` |
| 调用接口报 `WxApiConfig 未初始化` | 未调用 `WxApiConfig.set(...)` |
| 接口报 `40001` / `40013` | token 是否被其它实例挤掉；`appId` 与 `secret` 是否匹配（`40013` 为 appId 无效） |
| token 频繁失效 | `AccessTokenCache` 是否多实例共享；是否多进程共用同一 appId |
| 支付回调验签失败 | 是否用**原始请求体**（不能是重新序列化后的 JSON）；`PlatformKeySource` 是否能按 `Wechatpay-Serial` 返回平台公钥 |
| 支付请求报签名错误 | 私钥与证书序列号是否配对（序列号对应私钥）；`apiV3Key` 是否为 32 字符 |

## 8. 上线检查清单

- [ ] 应用自带 `aifei-all`，且未引入 `aifei-vip-arch` / `undertow` 等被禁止的依赖。
- [ ] `WeixinHandler` 注册在 `FrontHandler` 之前，回调地址为 `https://域名/weixin/{appId}/msg`。
- [ ] 公众号后台 Token / EncodingAESKey 与 `WeixinAccount` 一致。
- [ ] 回调链路无同步 Api 调用，业务处理在 5 秒内完成。
- [ ] 消息与支付回调均实现幂等。
- [ ] 生产环境使用共享 `AccessTokenCache`（多实例部署）。
- [ ] 支付侧已配置带客户端证书的 `SSLContext`（mTLS）与正确的 `apiV3Key`。
- [ ] 日志中不含 `secret` / `aesKey` / `apiV3Key` / 私钥 / `sessionKey` / 回调密文。
- [ ] `mvn clean test` 全部通过（含 `KernelBindingTest`）。

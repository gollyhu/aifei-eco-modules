## 二、验收标准矩阵（16 条 P0 / 75 条 AC）

> 用途：架构师做 AC↔实现映射、测试工程师做 AC↔用例映射（quality-gates §4「每条 P0 验收标准至少对应一条已执行用例」）。
> 说明：每条给出 AC 编号、Given/When/Then 原文要点、覆盖能力点。原文要点为忠实浓缩，关键断言值与异常/日志口径保留；完整原文见 PRD §6.1。

### REQ-P0-01 单条文案取用（3 条 AC）

| AC | Given / When / Then 原文要点 | 覆盖能力点 |
| --- | --- | --- |
| AC-01-1 | Given 某来源对 `key=login.title`/`locale=zh-CN` 有译文「登录」；When 以该 key+locale 取文案；Then 返回「登录」 | 单点命中基础路径（key+locale→译文） |
| AC-01-2 | Given 译文 `hello {0}`；When 取文案并传参 `Bob`；Then 返回 `hello Bob`；Given 传参数少于占位符个数；Then 缺参占位符**原样保留、不抛异常** | `{0}` 位置占位插值 + 缺参容错（注意与 AC-16-9「null 值→IAE」不同路径，见 §四(b)） |

### 3.2 四个配置键（恰好 4 个，无第五个、无启用开关；§5.7 / AC-12-1）

| 配置键 | 含义 | 必填 / 默认值 |
| --- | --- | --- |
| `i18n.defaultLocale` | 回退链终点语种；无显式/上下文/请求头时的生效语种 | **必填**，缺失即启动失败（AC-12-4） |
| `i18n.locales` | 支持语种列表（请求头匹配与导出合法性判断） | 可选；未配置=不做白名单（AC-12-6） |
| `i18n.sources` | 来源稳定名有序清单，顺序即叠加与回退顺序 | 可选；未配置默认仅 `properties`（AC-12-5） |
| `i18n.cache.ttlMillis` | 缓存 TTL | 可选；默认 60000；≤0 不缓存（AC-12-3/12-7） |

### 3.3 回退链唯一且不可配（§5.1/§5.3）

- 固定路径：**按 locale 逐来源 → 默认 locale 逐来源 → 返回 key 原文**。
- 未命中返回 key、**不抛异常**、DEBUG 日志；**无 strict 模式**（AC-03-3）。
- 来源运行期故障：视为该来源本次无译文并继续回退、**不向上抛**、WARN 日志（Q4 / REQ-P0-15）。
- 叠加顺序由 `i18n.sources` 声明顺序决定，先命中先返回，不可配其它语义。

### 3.4 locale 规范化规则（唯一定义点，§5.5 + §8）

- 规则：`_` 归一为 `-`、语言码小写、地区码大写、脚本码首字母大写。
- 示例：`zh_CN` → `zh-CN`；`zh-hant-tw` → `zh-Hant-TW`。
- 时机：**任何入参先规范化**，再参与后续全部动作（匹配、缓存 key 拼装、导出 `locale` 字段）。
- 匹配粒度：P0 仅做规范化后**精确匹配**；语言级宽松匹配（`zh`↔`zh-CN`）降 P1（REQ-P1-03 / A-4）。
- 非法 BCP 47：显式入参→IAE（AC-08-7/14-3）；请求头→静默忽略片段并继续（AC-08-8）。
- 登记于 §8「每类规则唯一定义点」，实现类不得复制。

### 3.5 语言包 JSON 契约四字段（§5.6）

```json
{ "locale": "zh-CN", "localeName": "中文（中国）", "dir": "ltr", "messages": { "login.title": "登录", "login.submit": "提交" } }
```

| 字段 | 硬约束 |
| --- | --- |
| `locale` | **规范化后**取值（§5.5）；导出显式传入、不受上下文影响（AC-09-4） |
| `localeName` | 由 JDK 内置 locale 能力得到（该语言在该语言中的名称），**禁语言名译名表**（AC-14-1 / §3.3④） |
| `dir` | 取值**只能来自 JDK 公开 API**（`ComponentOrientation.getOrientation(Locale)` 或等价），**禁语言码→方向映射表**（Q9 / AC-14-2）；能力不可用时降级 `ltr` + WARN、导出仍成功（AC-14-5） |
| `messages` | 有序映射；key 顺序稳定便于前端 diff（默认字典序 Unicode 码点升序，见 A-2）；value **恒为字符串**；下发**原文（含 `{0}`）**，占位符替换只在单条取文案时发生（Q6） |

### 3.6 dir 只走 JDK API（§5.6/§8/Q9）

- 判定：`ComponentOrientation.getOrientation(Locale)` 或等价 JDK 公开能力；源码审查断言**不存在语言码→方向映射表**。
- 依赖代价（§8 已知风险）：该 API 在 `java.desktop` 模块，**Java 9+ jlink 裁剪环境须保留 `java.desktop`**，否则判定不可用；Java 8 无模块系统不受影响。
- 降级：不可用时 `dir=ltr` + WARN，不阻断导出/不改 JSON 形状/不影响启动（AC-14-5）。

### 3.7 格式化薄门面、不自建规则数据（§1.1/§3.3/§5.8）

- 模块**只做一件事**：把「本次调用生效 Locale」正确传给 JDK 格式化 API，统一「值 + 维度参数 + locale」三参形态（日期类另加显式档位参数，四者正交）。
- **禁止自建**：CLDR 日期/数字模式串、货币符号表、语言码→方向表、百分比规则、货币小数位表——源码审查断言均不存在（AC-16-6）。
- 维度正交：币种独立传参（locale 不反推币种）、时区独立传参（与 locale 不互推）、小数位由币种决定（JPY/KRW 0 位、多数 2 位、BHD/KWD 3 位）。
- 数值字形由 JDK 决定（如 `ar-EG` 阿拉伯-印度数字、`ar-SA` 拉丁数字），模块不归一化、不提供「强制拉丁数字」选项。
- 无反向解析（单向）；不提供紧凑数字格式；不提供 pattern 透传。
- 异常语义：显式非法币种/时区→IAE；非法档位→IAE（或用枚举编译期类型检查，二者取其一、不得都不做）；null 值/币种/时区→IAE；locale 缺省→defaultLocale 不抛。

### 3.8 跨 provider 稳定断言口径（§5.8⑤ / D-03）

- 涉及 JDK 输出字面量的用例**只断言跨 provider 稳定的性质**：不相等 / 含本币种符号 / 月份名与「日」的相对位置 / 小数位；**不得写死符号字符与完整日期字符串**。
- 原因：`US$` 是 JRE provider 产物，CLDR provider 下可能不同；跨 JDK 差异由 JDK locale 数据决定，模块不承诺字节级一致。
- README 推荐 `-Djava.locale.providers=CLDR` 统一行为（Java 8 默认 JRE，Java 9+ 默认 CLDR）。

### 5.1 三处易混边界（非矛盾，供下游显式区分）

- **(a) `zh_CN_` ≠ `zh_CN`**：AC-08-7 / AC-08-8 / AC-14-3 的非法标识是 `zh_CN_`（**尾部多一个下划线**，规范化后 `zh-CN-` 悬空、非法 BCP 47，显式传参→IAE / 请求头→忽略）；AC-08-9 / AC-14-4 的 `zh_CN`（单个下划线，规范化后 `zh-CN`，合法并命中）。下游勿因字面相近而误判两处断言冲突。
- **(b) 缺参占位符 ≠ null 值**：AC-01-2 是「MessageFormat 风格位置占位**参数少于占位符个数**」，缺参占位符原样保留、不抛；AC-16-9 是格式化入口传 **null 值 / null 币种 / null 时区**，抛 IAE。属不同能力路径（文案插值 vs 格式化），且「缺参」≠「传 null」。
- **(c) locale 缺省 ≠ null 维度参数**：AC-16-5 / §5.8⑥ 明确「无显式 locale 且上下文为空 → 落 `i18n.defaultLocale`、不抛」（含未传 locale 的情形）；AC-16-9 的 null 指**值/币种/时区**。null 的适用范围不同——locale 缺失走默认值兜底，值/币种/时区为 null 抛 IAE。
